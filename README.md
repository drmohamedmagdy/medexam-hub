# MedExam Hub

AI-powered medical exam-prep platform. v0 slice: paid AI exam generator.

A user picks a specialty, topic, difficulty, and number of questions. The app generates clinically grounded MCQs via OpenAI, runs them in a practice or timed exam, then shows a graded result with per-question explanations and learning points. Monthly question quotas are enforced per plan (Free 20, Basic 500, Pro 2000, Premium 10000).

The free medical library, file upload + RAG, oral/OSCE modes, institutional plan, and Arabic localization from the full spec are not in this slice — they're scoped for later.

## Stack

- **Framework**: Next.js 16 (App Router, Turbopack) + React 19 + TypeScript
- **Styling**: Tailwind CSS v4
- **DB**: SQLite for dev (Prisma 7 with `@prisma/adapter-better-sqlite3`). Swap to Postgres for prod by changing `provider` in `prisma/schema.prisma` and `DATABASE_URL`.
- **Auth**: bcrypt + httpOnly cookie sessions (no NextAuth — Credentials provider doesn't work cleanly with DB sessions)
- **AI**: OpenAI Chat Completions with structured JSON Schema output, Zod-validated. Model defaults to `gpt-4o-mini`; override with `OPENAI_MODEL`.
- **Payments**: Stripe Checkout + webhook (optional). If `STRIPE_SECRET_KEY` is unset, `/plans` exposes a dev-only upgrade endpoint at `/api/dev/upgrade` so you can flip a user to a paid tier locally without configuring Stripe.

## Quick start

```bash
npm install
cp .env.example .env
# put your OPENAI_API_KEY in .env
npx prisma migrate dev
npm run dev
```

Open http://localhost:3000.

The smoke flow:

1. `/signup` — create an account (defaults to Free, 20 questions/month)
2. `/exam/new` — pick specialty, topic, difficulty, count
3. AI generates the exam (~20–60s), redirects to `/exam/{id}`
4. Answer the questions, submit
5. `/exam/{id}/results` — graded with explanations
6. `/dashboard` — usage, recent exams, average score
7. `/plans` — upgrade to Basic/Pro/Premium (uses `/api/dev/upgrade` if Stripe isn't configured)

## How quota enforcement works

Every `Question` row generated by the AI is logged in `UsageLog` with `kind="question_generated"` and a `yearMonth` field (`"2026-05"`). On every new-exam request `getMonthlyUsage` sums the current month's count and rejects requests that would exceed the user's plan limit. `recordUsage` writes the log only after a successful generation, so failed AI calls don't burn quota.

Per-plan limits live in `src/lib/plans.ts`. Update that one file to change pricing, monthly quotas, or per-exam caps.

## Stripe wiring (optional, for paid plans)

1. In the Stripe dashboard, create a Product with three monthly recurring Prices (Basic, Pro, Premium) and copy each price ID.
2. Add to `.env`:
   ```
   STRIPE_SECRET_KEY=sk_test_...
   STRIPE_WEBHOOK_SECRET=whsec_...
   STRIPE_PRICE_BASIC=price_...
   STRIPE_PRICE_PRO=price_...
   STRIPE_PRICE_PREMIUM=price_...
   ```
3. For local webhooks: `stripe listen --forward-to localhost:3000/api/stripe/webhook` and paste the printed `whsec_...` into `STRIPE_WEBHOOK_SECRET`.

When `STRIPE_SECRET_KEY` is set, `/plans` routes through real Checkout. When it's unset, the upgrade button calls `/api/dev/upgrade` and flips the user's plan directly.

## Production checklist (when you're ready)

- Switch `prisma/schema.prisma` provider to `postgresql` and run a fresh migration against your Postgres DB.
- Replace the `PrismaBetterSqlite3` adapter in `src/lib/db.ts` with `@prisma/adapter-pg` (or your preferred driver adapter).
- Set `STRIPE_*` env vars in your hosting platform; `ALLOW_DEV_UPGRADE` should remain unset.
- Add Google OAuth as a second sign-in option (per the spec) — easiest path is to bring back NextAuth and run it alongside the existing credentials sessions, or use `@auth/core` directly.
